## 1. 回测口径（全部复用线上同一套代码，不另造回测）

| 项 | 口径 |
|---|---|
| 样本 | 7 品种（MA/HC/Y/SM/FG/P/M）× 10 年主力连续日线，各 2440 根 |
| ATR | `cyc.atr_series(bars, 14)` Wilder，无未来函数 |
| 进场事件 | `sig_pack.build()` 的 `pred / warn / mw / confirm / tf` 共 **990 笔**（train 698 / test 292） |
| 执行 | 信号日 `i` 收盘生成 → 次日开盘 `i+1` 成交 |
| 出场 | `engine.exit_track()`：MA26 + 吊灯 3ATR + v24 容错（0.5ATR / 连 2 根 / 单根暴破 0.8ATR），叠加 30% 熔断（−3000 元），最长 60 根 |
| 收益 | `R = (离场价 − 进场价) × 方向 / ATR[信号日]` |
| 胜率 | `R > 0` 占比；盈亏比 `Σ正R / |Σ负R|`（与 `engine_v21.stats()` 同口径） |
| 样本外 | train ≤ 2023-11-30（与 v22 双段盲测切点一致）/ test 之后 |

**偏离度定义**（信号日 `i`，只用 `i` 及之前数据）：

```
LL = min(low[i-N+1..i])      HH = max(high[i-N+1..i])      C = close[i]
upPct = (C / LL − 1) × 100         距 N 日最低点涨幅（用户定义的主口径）
dnPct = (1 − C / HH) × 100         距 N 日最高点跌幅（做空对称）
upATR = (C − LL) / ATR[i]          用户要求的 ATR 口径
dnATR = (HH − C) / ATR[i]
pos   = (C − LL) / (HH − LL)       价格在 N 日区间的位置（0=底 1=顶）
```

**基准（990 笔全样本）**：胜率 40.7% · 盈亏比 1.56 · 均 R +0.552 · 净 R +546.1

## 7. 定稿阈值

```
回看 N = 60 个交易日
做多拦截：upPct = (C/LL−1)×100 ≥ 20%  且  pos = (C−LL)/(HH−LL) ≥ 0.90
做空拦截：dnPct = (1−C/HH)×100 ≥ 20%  且  pos ≤ 0.10
判定时点：信号生成日收盘（只用当日及之前 K 线，无未来函数）
拦截对象：pred / warn / mw / confirm / tf 五类【进场】信号
出场类一律不动：xsig / defend / 吊灯 / MA26 / 30% 熔断 / 白圈
```

**A1 的事件研究最终成绩**

| 组 | n | 胜率 | 盈亏比 | 均 R | 净 R |
|---|---|---|---|---|---|
| 被拦 | **38** | **28.9%** | **0.91** | **−0.094** | **−3.6** |
| 保留 | 952 | 41.2% | 1.59 | +0.577 | +549.7 |
| train 被拦 | 30 | 36.7% | 1.29 | +0.277 | +8.3 |
| **test 被拦** | **8** | **0.0%** | **0.00** | **−1.482** | **−11.9** |

被拦 38 笔：做多 23 / 做空 15；形态 `mw` 29 / `tf` 9；
品种 MA 13、P 7、HC 5、FG 5、Y 4、SM 3、M 1。
样本外 8 笔**全部亏损**，含用户指出的玻璃 2025-07-24，以及
2024-10-28 FG、2024-05-27 SM、2026-03-03 MA 等 30% 熔断案例。

**为什么选它**：① 满足用户设定的「胜率 <35%」触发线（28.9%）；② 样本外方向一致且更差；
③ 账本损伤最小且回撤几乎不变；④ 只拦 3.8%，界面不会被清空；
⑤ 能拦下玻璃那笔；⑥ N=60 与用户示例一致；⑦ 阈值较少、不易过拟合。

## 8. 必须说清的风险（不宣称「策略变好」）

1. **全 10 年 ATR 口径不支持这条铁律**：按用户最初写的「用 ATR 衡量」，被拦组胜率甚至更高。
   是改用**百分比 + 区间位置**双条件才切出坏区。这条结论与直觉相反，已完整保留在表 A。
2. **规律集中在近 3 年**：train 段被拦组 36.7% 胜率、净 R 仍为正，test 段才崩。
   可能是市场结构变化，也可能是阈值在同一批数据上反复试出来的**选择偏差**。
3. **样本外仅 8 笔**，统计功效不足；表格里 0% 胜率这个数字好看，但不能当作稳定估计。
4. **账本净收益 −7.2%（153,996 → 142,852）、胜率 −2.0pt、回撤 +0.7pt**。
   这是为「绝不追高杀跌」付的保险费，**不是收益优化**，不要把它写成策略改进。
5. 做多 / 做空两侧并不对称（表 D），当前按用户要求对称执行，后续可分别标定。
6. 建议每季度用新增数据重跑 `extreme_gate_backtest.py`，若样本外坏区消失应重新评估阈值。

## 9. 实现与「抹除」的边界

用户要求「抹除违规信号、图上和信号栏都不要显示」。实现上**没有**做前端隐藏或删历史记录，
而是在**引擎层让这些信号从未被接受**，再按新铁律重跑同一套 v22 方案账本：

- `extreme_gate.py`：阈值与判定单一真源（无未来函数）。
- `sig_pack.build(gate=...)`：信号包编译期剔除违规进场信号 → 引擎看不到它。
- `data_build.build_plan()`：传 gate → `plan.marks` 里不会出现「进多/进空」方块，
  `plan.full` 统计同步重算；`plan.verify`（v22 原始双段盲测报告）**保留不动**并加 `extGate.note` 说明口径差异。
- `data_build` 页面数组清理：`signals / mw / defend / defendSrc / sigW / sigM` 同步过滤，
  并清掉与被删信号成对的白圈，避免孤儿打叉。
- `daily.py`：新扫到的违规进场信号**不入库、不推送**，并打印被拦日志；
  `best_match()` 另加兜底。出场类 6 通道一条不动。
- `templates/pro.html`：「图上标记对照」与「当前生效口径」新增铁律说明，界面透明。

这样做的好处：**账本、看板逐笔清单、图上方块、信号栏四者仍然完全同源**，
不会出现「看板说做过这笔、图上却不显示」的账本撕裂。

**数据纪律**：以线上 `data/*.json` 为基线增量注入，不联网、不重算 K 线 / 分钟线 /
出场账本，`built` 保持 `2026-11-10 13:54`；`data/` 与 `dist/data/` 逐字节一致。
