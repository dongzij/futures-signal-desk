## 六、剩余风险与必须处理的事项

1. **PAT 已明文出现在对话截图中 —— 建议立即轮换。**
   GitHub → Settings → Developer settings → Personal access tokens → 撤销当前 token，
   新建一个（经典 PAT 勾 `repo`；细粒度 PAT 需 `Contents: read and write` +
   `Actions: read and write`），把新 token 写入
   `C:\Users\D\.config\futures-signal-desk\github_pat` 覆盖即可，脚本会自动读取。
2. **PAT 有效期**：若创建时选了 30/90 天，到期当天 15:20 会触发失败。
   建议设为长期有效并在日历记到期日。失效时 `--check` 仍能跑（只读），
   但派发会明确报「缺少 GitHub PAT」。
3. **WorkBuddy 自动化需应用在运行**：15:20 若电脑关机/应用未启动，主链路缺席，
   但 GitHub 内部心跳仍会在窗口内补上（这正是加心跳的目的）。
4. **数据源延迟**：若 15:20 时部分品种当日 bar 未出，`fresh_guard` 会
   5 轮 × 4 分钟重试到约 15:40；仍不齐则跳过，由心跳班次继续尝试，
   **不会**写入半截或陈旧数据。
5. **今天 15:20 是第一次真实写盘**：请以自动化任务回报的
   `built` / 7 品种末根 / `conclusion` 为最终验收依据。
