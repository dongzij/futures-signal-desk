## 一、盘感模拟模块（K 线点击 → T+1 开盘撮合）

### 设计口径

| 项 | 口径 |
|---|---|
| 成交价 | 点击 T 日 → 一律取 **T+1 日开盘价**；T 为最后一根时弹「次日开盘还没到，无法操作」 |
| 初始本金 | 100,000 元，可随时「追加资金」（正数追加 / 负数取出） |
| 合约乘数 / 保证金率 | 取 `data/index.json` products 里的真实值（玻璃 20 元/点 · 9%） |
| 手续费 | 开、平**双边**收取（玻璃 6 元/手·边），按手数线性 |
| 手数 | 弹窗内 ± 调整，上限 = 可用资金能开的最大手数，超限直接拦 |
| 估值基准 | `rpMarkAt(sym, 光标日)` 取「≤ 光标日」的最后一根**收盘价**，绝不用光标日之后的价 |
| 账本 | 独立 localStorage `fxreplay_v1`，与系统 `plan.marks` / `state.json` 零交集 |

### 三个防未来函数的硬约束

1. **成交价**：`bars[i+1][1]`，`i >= bars.length-1` 直接拒绝。
2. **估值**：浮盈只按光标日及之前的收盘算，往回翻历史时不会「提前知道后面涨了」。
3. **平仓**：同样走「T 日收盘决策 → T+1 开盘成交」，`exitIdx - entryIdx` 记成 `holdBars`。

### 交互实现要点

- ECharts 5 对 candlestick **不派发 series click**（实测命中元素 `type='normalCandlestickBox'`），
  所以改在 `CH.getZr().on('click')` 按 `e.target.type.indexOf('andlestick')` 分流，加 150ms 防重入。
- `convertToPixel({xAxisIndex:0}, i)` 返回**标量**；`convertFromPixel` 同样必须传**标量**（传数组返回 `null`）。
- 图上金色层：持仓成本虚线 + 开仓圆点「我多/我空 N」+ 平仓空心菱形，点线相连。

## 二、数据自动更新：今天为什么没更新，以及修了什么

### 事实（不是推测）

- 2026-11-11 白天 **9 个 cron 班次一个都没触发**，线上 `built` 停在 10:43，末根停在 11-10。
- 回看 11-04 ~ 11-10：schedule **每天只到 2 个班次**，且全部落在 UTC 15:04~17:50
  （北京时间 23:04 ~ 次日 01:50），完全在写盘窗口外。
- 延迟实测 **+7.6 ~ 9.6 小时**；分钟数全是 `:00`，正踩 GitHub 整点拥堵点。

结论：**问题不在 cron 写错，而在「整点班次被丢弃 + 延迟叠加」**。

### 已修（v28.1）

1. **cron 全部错峰**（不再用 `:00`）
   - `daily.yml`：`23 0,2,4` / `41 1,3,5` / `53 13,14`
   - `guard.yml`：`07 0,2,4` / `29 1,3,5`
   - 目标：延迟叠加后，UTC 00~05 的班次才会落到北京 15:00~21:00。
2. **分钟线夜盘截断**：`_asof_trim` 原来只比日期，夜盘 bar 被数据源标成「当天 21:15」，
   于是 21:08 那班把 21:15 / 22:00 两根半截 bar 写进了 m15 / m60。
   现在「同日且时间 > 15:00」一律剔除（日盘 15:00 收盘，之后必是夜盘）。实测已清干净。
3. **late 班次打通**：`fresh_guard` 输出 `run_mode=late` → `nightgate` 认 late 放行。
   历史上 21:00 / 22:00 兜底班次必挂（exit 3）的根因就是这两处没接上。

### 仍然存在的客观限制（必须说清楚）

GitHub 官方规则：schedule 是 best-effort，高负载会**延迟或直接丢弃**。本仓库实测丢弃率约 80%。
所以「密集网格」只能提高命中率，**无法保证 100%**。

要做到「一定」，只有一条路：外部定时器打 `repository_dispatch`（仓库已支持该事件）：

```
POST https://api.github.com/repos/dongzij/futures-signal-desk/dispatches
Authorization: Bearer <PAT>
{"event_type":"daily-scan","client_payload":{"force":"0"}}
```

cron-job.org / 腾讯云函数 / 任意免费定时器，北京时间 15:25、15:55 各打一次即可，与本机完全无关。
另：即使某天真漏跑，第二天那班会连当天一起补上（取数拿的是全历史），数据不会错，只会晚一天。
