# v21 回测引擎重构报告

> 口径：1 万元本金 / 每次 1 手 / 资金不足自动追加 1 万 / 30% 本金熔断 / 次日开盘成交。
> 数据区间：2016-10 ~ 2026-11（尿素自 2019-11 上市起算）。核心池 6 个品种，按要求把 JD 单独列出对照；策略手册部分 JD 因双段不合格被判不交易。

## 0. 先给结论

1. **旧引擎确实错了**：它把"反向信号"当成唯一出场条件，导致持仓可拖 374 天。新引擎把【失效/强烈离场】提到第一优先级后，**3,529 笔交易里最长持仓 74 天、平均 12.6 天**；单笔亏损被 30% 熔断压在 −3,000 附近，但跳空会穿透——全样本 8 笔超过 −3,100，最深 −3,412（FG 2023-08-15 开盘跳空越过熔断价）。
2. **逆势是唯一稳定亏钱的姿势**：6 品种 10 年样本里，趋势中做反向信号（顶底雷达逆势 0% 胜率 / 平均 −2.76R，WM 结构逆势 0% / −3.05R）。这不是概率问题，是方向问题。
3. **进场预警单独做是亏的**：6 个品种全亏（−2,316 / −3,496 / −6,536 / +2,224 / −8,840 / −5,454），胜率仅 16~29%。它只能当"观察提示"，不能当开仓指令。
4. **没有一套公式能通吃**：15 个候选策略 × 6 品种，只有"D3 动态·保守"在 3 个品种上同时通过训练段与验证段。UR / RB / JD 全部候选策略双段不合格。
5. **样本外是照妖镜**：UR 的转折确认策略全样本 +25,372 元（年化 20.1%），但拆成训练/验证两段后，验证段 **−11,808 元、回撤 118%**。上一版按全样本选"最优"的做法会把这个坑当成机会。

## 1. 模块一：回测底层规则（重写）

### 1.1 时序纪律（无未来函数）

| 环节 | 规则 |
|---|---|
| 信号生成 | T 日收盘后 |
| 开仓成交 | T+1 开盘价 |
| 失效 / 强烈离场 / 破 MA26 / 吊灯 | T 日收盘确认 → T+1 开盘平仓 |
| 30% 本金熔断 | 盘中触及即平，按触发价成交（唯一不等收盘的规则） |
| 保证金不足 | 开盘前检查，不足 1 手即追加 1 万元 |

### 1.2 平仓优先级（逐日裁决，严禁死扛）

| 顺位 | 触发条件 | 动作 |
|---|---|---|
| 第一 · 防守 | ① 本仓信号被判失效（白圈）；② 出现指向本仓的强烈离场雷达 | 立刻平仓，先下车 |
| 第二 · 底线 | 收盘跌破（多）/涨破（空）MA26；或吊灯触发（自持仓极值回撤 ≥3.0 ATR） | 平仓 |
| 第三 · 反手 | 必须"原仓已平"且"当日出现反向进场信号" | 才允许反向开仓 |

> 关键改动：反向信号**不再**能直接反手。若原仓既没失效、也没破线，反向信号一律忽略（记入审计日志）。这就是"先下车、再等新信号"。

### 1.3 资金机制

| 项目 | 规则 |
|---|---|
| 初始本金 | 10,000 元 |
| 手数 | 固定 1 手，不加仓、不金字塔 |
| 资金不足 | 每次追加 10,000 元，可多次追加，逐次计数 |
| 输出 | 追加次数 / 总投入本金 / 期末剩余资金 |

### 1.4 新旧引擎的硬对比（同一品种、同一信号源）

| 指标 | 旧引擎（v20） | 新引擎（v21） |
|---|---|---|
| 出场逻辑 | 只能等反向信号 | 失效/强离场 → MA26/吊灯 → 反手 |
| 最长持仓 | 374 天（玻璃） | **74 天**（玻璃 2024-06-14 空单，全策略样本最大值） |
| 平均持仓 | 20~60 天 | **12.6 天**（3,529 笔均值） |
| 单笔最大亏损 | 未受控 | **−3,412 元**（30% 熔断 + 跳空穿透，8/3,529 笔超 −3,100） |
| 资金不足 | 直接跳过信号 | **自动追加 1 万并计数** |

## 2. 模块二：路况分析表（先看路，再上信号）

### 2.1 量化标准（落地口径）

**大趋势**（三条同时成立）：
- 幅度：从摆动起点到终点，涨跌幅 ≥12% **或** 空间 ≥3×日线 ATR（满足其一）
- 持续：≥15 个交易日
- 斜率：该段 MA34 净位移 ≥2.0 ATR（全样本约 42% 的天数能达标，对应"明显倾斜"）

**震荡市**（三条同时成立）：
- 窗口：20 个交易日（用户给 15~30，取中值）
- 振幅：(窗口最高 − 最低) / 均价 < 10%
- 穿梭：收盘在 MA34 上下穿越 ≥3 次
- 走平：窗口内 MA34 位移 < 窗口振幅的 50%

> 走平为什么要用"相对振幅"而不是固定 ATR？实测 MA34 的 20 日位移中位数是 1.46 ATR，用 0.6 ATR 当"走平"会把 80% 的时间判成走平，与"穿梭 ≥3 次"几乎互斥（共现率 0.02%）。改用相对振幅后，震荡占比落到 8~15%，与肉眼判断一致。

> 这里有个必须先讲清楚的事实：**"过渡态"才是信号的主战场**（占 40~50% 时间）。只按"趋势/震荡"二分，会把一半以上的交易机会划到规则之外。所以下面的体检表保留"过渡"一列，不硬塞进趋势或震荡。

## 6. 这一版推翻了上一版的什么

| 上一版（v20）结论 | 这一版（v21）实测 | 为什么推翻 |

| 每品种都有"最优方法"，胜率 45~74% | 只有 3/6 品种双段合格，胜率 28~53% | 上一版是全样本内选优，含选择偏差；拆样本外后大量失效 |
| 玻璃 374 天持仓合理 | 该笔在新引擎里不存在 | 旧引擎只在反向信号时出场，属于"死扛" |

| 30% 熔断增厚收益 | 熔断只做风控，不做收益 | 修正判断写反的 bug 后，熔断是纯成本 |

## 8. 复现方式

全部脚本确定性运行，无随机数、无时间依赖，同一份数据必然得到同一结果：

```bash
python signal_audit.py        # 模块三：1,050 条信号的场景体检
python audit_by_sym.py        # 模块三：分品种体检（导出 CSV）
python run_v21.py             # 模块四：15 策略全矩阵
python run_oos.py             # 模块四：训练/验证双段验证
python report_v21.py          # 生成本报告
python export_v21_tables.py   # 导出四张表
python audit_trades.py M D3   # 单品种逐笔审计（可换 UR/FG/MA/RB/JD 与任意策略码）
```

自检口径：任意一笔交易的 `开仓日 = 信号日 + 1 个交易日`，`开仓价 = 当日开盘价`；
`max(持仓天数) = 74`；`min(单笔净盈亏) = -3412`（30% 熔断价 + 开盘跳空穿透）；`追加次数 = ⌈资金缺口 / 10000⌉` 的累计。
