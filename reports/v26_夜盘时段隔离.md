# v26 · 夜盘时段与 K 线彻底隔离

> 一句话：23:10 那班改成「只看不写」，并且从物理上让它**没有能力**写。

---

## 1. 发现的问题（已修）

用户把 23:10 的 cron 加到了 `.github/workflows/daily.yml` 的 `schedule` 里：

```yaml
schedule:
  - cron: '20 7 * * 1-5'   # 15:20
  - cron: '50 7 * * 1-5'   # 15:50
  - cron: '10 15 * * 1-5'  # 23:10  ← 新加
```

cron 加对了，但**那条 job 是完整写入流程**：`daily.py` → `data_build.py`（先 `os.remove` 清空 `dist/data`）→ `render.py` → `git add -A state.json dist/ data/` → `git push`。

后果有三层，一层比一层重：

| 层 | 会发生什么 | 后果 |
|---|---|---|
| 数据 | 日线接口在夜盘时段可能已吐出「下一交易日」的未完成 bar | K 线多一根半截假 bar，**永久**留在图上 |
| 账本 | `daily.py` 用夜盘口径跑完直接写 `state.json` | 持仓、信号去重、成交记录被半截行情改写 |
| 页面 | `built` 时间戳变成 23:1x | 用户以为「今天收盘数据已更新」，实际是夜盘临时值 |

夜盘 21:00-23:00 按交易所口径属于**下一个交易日**（周五夜盘属于下周一），
所以它连「今天的收盘价」都不是 —— 这一点决定了它绝对不能进 K 线。

## 2. 三班职责（现在是硬隔离的）

| 班次 | 文件 | cron（UTC） | 北京 | 写 state | 写 data | 推送 |
|---|---|---|---|---|---|---|
| 正式收盘 | `daily.yml` | `20 7 * * 1-5` | 15:20 | ✅ | ✅ | 6 条通道 |
| 兜底重试 | `daily.yml` | `50 7 * * 1-5` | 15:50 | ✅ | ✅ | 同上 |
| 盘中预警 | `intraday.yml` | `33 3 * * 1-5` | 11:33 | ❌ | ❌ | 命中才推 |
| **夜盘预警** | **`night.yml`** | `10 15 * * 1-5` | **23:10** | ❌ | ❌ | 命中才推 |

**11:33 的盘中预警原样保留**，`intraday.yml` 一个字没改。

## 3. 夜盘预警判什么（night_warn.py）

把「今晚 21:00 到 23:00」压成一根 bar，`d` 标成**下一交易日**，放进日线序列末尾，
用**同一套** `engine` / `defend_rules` / `mw_events` / `regime_lib` 复跑一遍，
与今日收盘口径比差异。命中才推，不命中零输出。

| 触发 | 数据来源 | 文案 |
|---|---|---|
| 白圈 / 吊灯 / 破 MA26 / 持有到期 | `audit` 里 `act=signal_exit` 且 `t=最后一根` | 「夜盘收盘裁决出场：… 明早开盘执行」 |
| 30% 熔断（夜盘当场打穿） | `trades` 里 `exit_date=夜盘交易日` | 「夜盘已触发 30% 熔断，明早开盘无条件处理」 |
| 路况翻成趋势 | `regime_lib.causal_regime(夜盘 bar)` vs 今日 plan | 「进入可开仓区 / 路况翻转（持仓中）」 |
| 持仓逆向 ≥0.5 ATR | 按持仓方向取最不利一侧 ÷ ATR | 「夜盘逆向 1.2 ATR」 |

**一个必须记下来的坑**：引擎的出场是「收盘裁决 → 次日开盘执行」，
平仓动作记在 `pending[t+1]`，最后一根 bar 的裁决**永远执行不到**，
所以它只留在 `audit` 里，`trades` 里什么都没有。
第一版按 `trades` 找出场，实测即使造一根跌 9% 的 bar 也一条都不出 —— 死代码。
现在改成读 `audit`，造 −5% 即可正确命中「收盘跌破 MA26（缓冲 0.5ATR）（连 2 根）（单根暴破 0.8ATR）」。

**静默规则**（与「震荡只静音进场」同源）：
- 空仓 + 仍是震荡/过渡 → 不推
- 空仓 + 路况翻成趋势 → 推（明早可能开仓）
- 持仓 + 逆向 <0.5 ATR 且无出场裁决且路况未变 → 不推

## 4. 四道防污染保险

1. **`night.yml` 权限只读**：`permissions: contents: read`，脚本写错也推不上去。
2. **`git status` 断言**：跑完检查工作区，只要有任何改动就 `exit 1` 判失败。
3. **`nightgate.py` 代码闸门**：北京时间 20:00-08:00，`daily.py` / `data_build.py` 第一行就 `exit 3`。
   即使 cron 又被加错、或有人半夜手动 dispatch，也写不进去。
   15:20 / 15:50 永远在窗口外；人工补数用 `RUN_MODE=force`。
4. **`intraday_warn.py` 时段断言**：它的 `live_bar()` 会把「今日日盘 + 昨日夜盘」拼一根，
   在 23:10 跑会得到「今日日盘 + 今晚夜盘」的混合体，直接拒绝在 09:00-15:00 之外执行。

另外 `night_warn.py` 自身不 import `daily`（那条链路带 state 写入），
`post_push` 是独立实现的 10 行；基线不是「今天」就整品种跳过，绝不拿旧数据瞎比。

## 5. 验证记录

| 项 | 结果 |
|---|---|
| 闸门时间判定 | 15:20 / 15:50 / 16:40 → 放行；20:00 / 21:05 / 23:10 / 02:30 / 07:59 → 拦截；08:00 → 放行 |
| 闸门实际拦截 | 模拟 23:10 调 `enforce('daily.py')` → exit 3，日志给出替代命令 |
| 无夜盘数据 | 16:xx 实跑：7 品种全部「今晚无夜盘数据」跳过，0 推送 |
| 基线过期 | 今日 15:20 数据未到 → 7 品种全跳过 + `::warning::` 注解（不推微信，避免噪音） |
| 出场裁决分支 | FG 造 −5% 夜盘 → 正确命中「收盘跌破 MA26…明早开盘执行」 |
| 熔断分支 | 造 −8~9% 时先由 MA26 兜住（优先级正确），熔断分支由 `exit_date` 命中 |
| 真实历史回放 | M 11-05 夜盘 +1.5% / 1.22ATR → 推「逆向 1.2 ATR」；P 11-05 +2.95% / 1.47ATR → 推「1.5 ATR」；HC 0.36ATR → 静默 |
| 页面 / 数据 | 本次改动不涉及 `templates/`、`data_build` 输出结构，页面零变化 |

## 6. 已知限制

1. **交易日历用「下一工作日」近似**：节假日无法预判。节前夜盘若存在，`d` 会落在节假日，
   但夜盘 bar 只在内存里，不影响任何落盘数据，最多让文案日期差一天。
2. **夜盘只覆盖 21:00-23:00 的直观判断**：代码里窗口是 `21:00-次日03:00`，
   若以后扩到 01:00 / 02:30 收盘的品种也能直接用，无需改逻辑。
3. **无夜盘品种自动跳过**：按分钟线实际有无判断（实测 SM 无夜盘 bar，FG 有，以数据为准，不硬编码）。
4. 夜盘推演基于「明早开盘 ≈ 夜盘收盘价」的假设，日盘跳空仍有偏差 ——
   所以文案统一写明「只用于明早应对，正式结论以 15:20 为准」。
