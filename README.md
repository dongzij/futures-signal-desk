# 期货信号台 · 腾讯云部署说明（v4 反转预测雷达版）

## 这是什么
一个**反转预测系统**，只针对玻璃 / 豆粕 / 螺纹钢 / 甲醇 / 尿素五个品种回测与运行。
以 MA34 定义大趋势（收盘价上/下方＝一段趋势，穿越点＝反转点；20/25/30/34/40/45/50
七个周期逐一回测，**34 的收益与回撤同时最优**）。对历史上每个反转点做事件研究：
反转前 10 根内的共性变化，经 20 条候选特征筛选，保留区分度最高的 **4 条**
（逼到 MA34 ≤0.3ATR · 10 日累计逆行 ≥1.5ATR · MA10 斜率转向 · MACD 柱翻向），
命中条数直接标定反转概率（首轮触发实测：5 日内 69.4%，36 笔）。
另加 **ADX(14)≥20 趋势门槛**：剔除"趋势还没起来"的震荡信号，胜率由 33.3% 提到 40.0%。
**强确认层（v5 失误专项分析）**：36 笔首轮触发中 11 笔失误，其中 9 笔在信号日
持仓量 5 日仍在增加（趋势资金未撤离）。叠加「持仓 5 日下降 + 自极值回撤 ≥2ATR」后
19 笔中 17 笔 5 日内反转（**89.5%**，内 91.7%/外 85.7%），不设止损收益 +18.7R→+26.5R、回撤减半。
命中 4 条且 ADX 达标 → **准备反转·可建仓**（首轮触发实测 5 日内 69.4%）；
再满足强确认两条 → 概率升至 89.5%（微信推送只推强确认档，≥70% 阈值）；
放量类与持仓减仓类指标经检验无区分度（lift<1），已淘汰。

## 口径（与回测完全一致，无前视）
- 触发：段内 4 条特征全部命中且 ADX≥20（每段趋势最多一次，方向唯一；新段至少站稳 2 根）
- 入场：命中次日开盘，按预测方向（顶→空 / 底→多）
- 出场：**不设止损**——一直持有，直到收盘反向穿越 MA34（新趋势走完）才离场；250 根安全上限仅防数据异常
- 成绩（10 年 5 品种，线上引擎口径）：36 笔，胜率 36.1%，盈亏比 3.0，年均约 3.6 笔，累计约 16,000 元/手
- 强确认层：19 笔，5 日内反转 89.5%，交易收益 +26.5R（占全部收益的大部分）
- ⚠ 不设止损的代价：持仓期浮亏中位 0.95 ATR、最深 8.7 ATR（约 8,900 元/手），务必小仓并预留浮亏空间
- ⚠ 收益集中于少数大行情，存在连续小亏期；本系统定位是"高可靠预警层 + 小仓试单"

## 文件
- engine.py     信号引擎（MA34 趋势段 + 4 特征雷达 + ADX 门槛 + 概率标定）
- model_v4.json 概率标定模型（引擎启动时读取，必须随包上传）
- daily.py      每日任务：扫描 → 推进持仓（无止损，反向穿越离场）→ 按概率阈值推送 → 写 state.json
- data_build.py 构建分品种数据包（dist/data/*.json，含实时雷达状态）
- render.py     生成静态页 dist/index.html
- serve.py      零依赖手机页服务（http.server + Basic Auth + gzip）
- notify.py     微信推送（pushplus，仅推概率 ≥70% 的建仓信号）
- build.py      新浪行情抓取与缓存
- config.json   品种池 / 本金 / 浮亏预算比例 / 推送 token / 网页账号密码
- install.sh    一键部署

## 服务器上部署（已装好旧版 → 3 条命令升级）
```
# 1. 上传 tencent-bot-v4.zip 到服务器（scp 或宝塔面板）
# 2. 解压覆盖旧目录（旧 state.json 会重建，历史信号自动重算）
unzip -o tencent-bot-v4.zip -d ~/futures-bot && cd ~/futures-bot
# 3. 重跑初始化并重启服务（拉历史约 5~10 分钟）
python3 daily.py && python3 data_build.py && python3 render.py
sudo systemctl restart futures-web
```

## 全新部署（2 条命令）
```
unzip tencent-bot-v4.zip -d futures-bot && cd futures-bot
bash install.sh
```
完成后终端会打印访问地址 http://<服务器IP>:8000。

## 配置微信推送（2 分钟）
1. 微信扫码登录 pushplus.plus（免费）
2. 复制你的 token，填进 config.json 的 "pushplus"
3. 重跑 python3 notify.py 或等下一个交易日 15:10

## 定时
cron 已配两个时点（15:10 与 15:40 重试），周一至五自动跑：
扫描 → 重建数据包 → 渲染页面 → 推送。日志：tail -f ~/futures-bot/cron.log

## 安全建议
- 防火墙只放行 8000 端口（和 SSH 22）
- config.json 里的网页账号密码（user/pass）建议改掉默认值


## v8 趋势跟踪模块（2026-11-04 新增）

**动机**：玻璃 2026-03→10 的 7 个月空头（−400 点），反转雷达零信号——该顶部无任何
"过热/放量"特征（全程 ADX 7~20、偏离 MA34 最大 2.6ATR），反转指纹结构上抓不到。
趋势跟踪是唯一能吃到这类行情的路径。

**参数寻优**（ZigZag 确认反手，5 品种 / 10 年，训练 2016-2023 / 盲测 2024-2026）：
- 30 组参数里只有「自极值回撤 3.5×ATR 确认 + 最多持 40 根」训练盲测双正
- 成绩：254 笔、胜率 48.8%、累计 +136R、最大回撤 −27.3R、年均约 25 笔
- 多空对称（多 +72R / 空 +62R）、五品种全正（FG +42.5 / M +34.6 / RB +22.5 / MA +29.0 / UR +7.4）
- 去掉最大 5 笔仍 +73.5R；年度 8/11 年为正
- 代价：中位单笔 −0.25R（靠盈亏比赚钱）；反抽洗盘会被洗出去（玻璃 2026 全年仅 −1.3R）

**段定义检验**（用户假设"大周期定义过严"）：
- "持续≥20根 或 幅度≥200点" 与现行"≥15根且≥3ATR"几乎等价（37 vs 36 笔、+19.5R vs +20.2R）
- 彻底去掉大周期段过滤：60 笔 +32.5R，胜率/单笔不变——但有强确认层时结果完全一样，
  说明瓶颈不在段定义，在信号本身
- 价格结构（ZigZag）定义下旧 4 条特征 lift 全部 <1（原来的"贴近MA34/回撤2ATR"
  是对 MA34 交叉标签的循环论证成分），真有区分度的是"过度延伸+单日振幅+ATR放大"
  组合（5 日 +0.58ATR、胜率 67%，但 10 年仅 27 笔）

**两模块关系**：反转雷达＝趋势末端探测器（入场早、信号少、靠强确认保证质量）；
趋势跟踪＝趋势确认层（入场晚、信号多、靠盈亏比赚钱）。两者独立仓位、独立预期。
